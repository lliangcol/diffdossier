# 任务状态与证据记录约定

本约定落实 `DD-CTRL-002`，适用于
[`2026-07-27-productization-todo.md`](2026-07-27-productization-todo.md)
中的每一项任务。它补充而不替代计划的“状态与执行协议”。

## 同轮记录规则

只要一轮工作改变任务状态、任务定义、实现、文档或验收证据，就必须在同一
工作树变更集中完成下列记录：

1. 更新任务表中的状态与实际 `updated_at`；任务开始先转为 `in_progress`，
   仅在依赖、验收证据和相关文档均满足时转为 `completed`。
2. 在计划“执行日志”追加一行，写明任务 ID、旧状态到新状态、时间、证据摘要
   和剩余风险或下一步。历史行不得改写。
3. 将可复现的证据与改动一起落盘，或在日志中给出稳定的命令、完整 SHA、
   run URL 或外部来源；记录其查询时间和证据级别。远端/API 读取失败必须记为
   `unknown` 或 `blocked`，不得写成通过。
4. 在开始任何后续工作包前，完整执行
   [`execution-baseline-checklist`](2026-07-28-execution-baseline-checklist.md)，
   并把其八项结果附为一节新的执行记录。
5. 区分工作树、暂存区、提交和远端状态；暂存、提交、推送、PR、合并、Release
   及其他外部写操作仍须有本计划所要求的单独、精确授权。

## 最小迁移记录

每一条状态迁移至少包含以下字段：

| 字段 | 要求 |
|---|---|
| 任务 ID | 计划表中的唯一 ID。 |
| 状态变化 | 明确的旧状态和新状态。 |
| 时间 | 带时区的实际 ISO 8601 时间。 |
| 证据 | 文件路径和变更摘要，或命令、完整 SHA、run URL、外部来源及查询时间。 |
| 下一步/风险 | 未闭合的依赖、人工门禁、验证或后续任务。 |
| 交付边界 | 是否发生暂存、提交、推送或其他外部写操作；未发生时明确写出。 |

若后续修改使已完成任务的证据失效，应在同一规则下把任务退回 `pending` 或
`in_progress` 并说明原因。该规则不把本地 `PASS`、已有 CI 或旧外部快照扩大为
发布、合并或上线批准。

## 本次示例

计划执行日志中 `2026-07-28T11:14:07+08:00` 与
`2026-07-28T11:15:12+08:00` 的 `DD-CTRL` 记录提供首次完整示例：它们包含
清单的完整复跑、`DD-CTRL-001` 的完成依据，以及 `DD-CTRL-002` 从 `pending`
到 `in_progress` 再到 `completed` 的记录。没有执行任何 Git 交付或外部写操作。
