# Configuration contract

DiffDossier normally layers the optional platform user configuration below the
required `<repo>/diffdossier.toml`. Repository scalar fields override user
fields; a declared repository `[[gates]]` array replaces the user Gate array.
Omitted fields inherit from the next lower layer and then built-in defaults.

`--config` overrides `DIFFDOSSIER_CONFIG`; either selects one exact file over
built-in defaults instead of merging the normal user and repository files. A
relative selected path is resolved against the canonical repository root.
`--baseline` is the highest-precedence semantic override and its value is
included in the effective configuration digest used by snapshot freshness.

`--state-dir` overrides `DIFFDOSSIER_STATE_DIR`, and `--cache-dir` overrides
`DIFFDOSSIER_CACHE_DIR` where cache diagnostics are exposed. State and cache
overrides must be absolute. These are the only allowlisted `DIFFDOSSIER_*`
configuration variables; secrets are excluded from every layer.

Schema version 1 rejects unknown fields and unsupported versions. There is no
predecessor to migrate. Future versions must provide an explicit dry-run
migration or reject input; they must never reinterpret an old document
silently.

The baseline field is required. DiffDossier does not guess main or master, and
resolving a local ref is not evidence that the remote is fresh.

To create a minimal command-free repository configuration, provide an explicit,
locally resolvable baseline:

    diffdossier init --repo /absolute/repository \
      --baseline refs/remotes/origin/main --json

`init` resolves the Git repository root, verifies the baseline locally, and
publishes `diffdossier.toml` through an exclusive same-directory staging file.
It refuses every existing target, including a symlink, and never overwrites or
enables a Gate. Concurrent initializers can publish at most one complete valid
file. It does not fetch, inspect credentials, execute project commands, create
runtime state, or claim the local baseline is remotely fresh.

    diffdossier config validate --repo /absolute/repository
    diffdossier config validate --repo /absolute/repository --json
    diffdossier doctor --repo /absolute/repository --json

`config validate` reports the effective configuration digest and source
digests. `doctor` is read-only: it reports resolved state/cache paths, effective
configuration metadata, local-only baseline resolution, discovered
`AGENTS.md`/`CLAUDE.md` paths and scopes, and same-scope non-identical rule
conflicts as `needs_confirmation`. It never fetches or executes a configured
Gate, Provider, repository command, or network request.

The logical JSON model is published in schemas/config.schema.json. The TOML
surface accepted by the current parser is demonstrated by
diffdossier.example.toml; unsupported TOML features fail closed.
`diffdossier.example.toml` includes a Go Gate as an illustrative, untrusted
candidate. The minimal file generated by `init` deliberately contains no
Gate; the target repository owner must add and separately authorize exact
commands.

Optional risk policy files use the strict format shown in
policies/risk.example.toml. Policy rules may raise inferred risk but can never
lower it. Invalid, missing, escaping, or unknown policy input blocks planning.

Each `[[gates]]` entry declares argv (never a generated shell string), cwd,
environment allowlist, path selectors, dependencies, timeout, resource and
network classes, cache class, blocking/final behavior, expected writes, and a
redaction policy. `gates plan` resolves and hashes the executable and allowed
environment values but never starts the command. The example configuration is
the canonical TOML surface.

Only `worktree_deterministic` evidence can be reused, and then only for the
same snapshot, expanded definition, DiffDossier binary, executable, and
toolchain inputs. `host_volatile`, `time_network`, and `external` always rerun;
`final_always` bypasses cache during finalization.
